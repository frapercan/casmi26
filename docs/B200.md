# Fast-iteration runbook (B200 / H100 class GPU)

Goal: turn a short window on a big GPU into as many *informative* experiments as
possible. Everything below is scripted; nothing needs Kaggle once the data is local.

## 0. Before the window (no GPU needed)
- Have a Kaggle API token for the box (`KAGGLE_API_TOKEN`), and the repo cloned.
- Decide the experiment queue (`exp/*.json`) in advance; see section 3.

## 1. Setup (~1 h, mostly CPU + embeddings)
```bash
KAGGLE_API_TOKEN=... bash scripts/setup_b200.sh /data
```
Downloads competition + candidate data, builds the spectral library, the 18M
candidate table, the class-2 holdout, centred ChemBERTa embeddings, the SAE and the
JEPA encoder, then runs a throughput benchmark (`exp/b200_bench.json`).
Every step is skipped if its output exists, so re-running is safe.

## 2. What makes it fast
| | Kaggle T4 (v1) | big GPU path |
|---|---|---|
| batch assembly | Python loop, CPU (23 ms) | `GPUStore`: whole train set on GPU, pure indexing |
| precision | bf16 emulated → fp16 | native bf16 (`--amp auto`) |
| graph | eager | `--compile` |
| host sync | `.item()` every step | only when logging |
| JEPA sampling | 1.9M permutation per step | O(batch) |
| GPU use | 1 run | `--parallel N` runs share one GPU |

The model is small (~10M params), so one run leaves a B200 mostly idle. Use
large batches (`--batch 1024..4096`, scale `--lr`) and/or `tools/sweep.py --parallel 4`.

## 3. Running experiments
```bash
python tools/sweep.py exp/reg.json   --work /data/work --parallel 4
python tools/sweep.py exp/scale.json --work /data/work --parallel 2
python tools/report.py /data/work/results.jsonl
```
Each run appends one JSON line (tag, commit, args, final holdout MRR, time) to
`results.jsonl`; finished tags are skipped on re-run, so sweeps resume after a crash.

Prepared queues:
- `exp/b200_bench.json` — throughput at batch 256/1024/4096 (run first).
- `exp/reg.json` — overfitting fixes: dropout, weight decay, harder mass-local batches.
- `exp/scale.json` — model width/depth.

## 4. Caveat: the validation metric
`train.py` reports class-2 holdout MRR against DB candidates only (v2: 0.50). The full
pipeline (`eval_fusion.py`, library candidates included) gave 0.28-0.36, and the public
LB gave model-only 0.122. So the training metric ranks *model variants*, but final
decisions need `eval_fusion.py` on the winners, and ideally a validation set closer
to the hidden test (timsTOF, natural products, library molecules in the pool).

## 5. Bringing a model back to Kaggle
Upload `runs/.../best.pt`, `runs/sae.pt`, `emb/plm_mean.npy` and the ChemBERTa folder
as a private Kaggle dataset, then point the submission kernel at it.
